# Общая сессия ZenithOpus: интернет и LAN

Сборка рассчитана на Minecraft Java **1.21.11**, Fabric Loader **0.19.2+** и Fabric API **0.141.6+1.21.11**. На втором ПК достаточно обычного Minecraft Java **1.21.11**, установка ZenithOpus там не требуется.

В режиме **«Через интернет»** клиент сам подключается к публичному ретранслятору e4mc и получает временный адрес `….e4mc.link`. Не нужны Playit, VPN, отдельные программы, аккаунт, VPS или настройка портов на роутере. Библиотеки туннеля, включая нативные файлы для Windows x64, Linux x64/ARM64 и macOS x64/ARM64, уже упакованы в JAR; при запуске функции они не скачиваются. Ретранслятор является внешним сервисом, а основной Minecraft и его соединение с игровым сервером продолжают работать на твоём ПК.

В режиме **«В одной сети»** устройства подключаются напрямую по локальному IPv4, без обращения к ретранслятору.

1. Установи собранный `build/libs/zenith-1.0-SNAPSHOT.jar` в `mods` основного клиента, заменив предыдущую сборку Zenith. Запусти игру и зайди на нужный сервер.
2. Нажми **Esc → Подключить сессию → Через интернет → Создать и войти**. Для локальной сети выбери **«В одной сети»**.
3. Дождись адреса в окне приглашения и скопируй его. Для Интернета это `….e4mc.link`, для LAN — `192.168.…:порт`. На втором ПК открой **Сетевая игра → Прямое подключение**, вставь адрес и войди. Название в списке серверов — **ZenithOpus · Общая сессия**.
4. Сначала второй ПК находится в режиме просмотра: отдельная камера плавно следует за основным игроком, а игровые действия не передаются на сервер. Скопируй секретную команду из фиолетового поля и введи её в чат второго ПК: `/zo… take`. Она обрабатывается локально и не отправляется на игровой сервер. После подтверждения позиции управление получает второй ПК; команда `/zo… release` возвращает его основному ПК и снова включает просмотр.
5. Управление получает второй ПК. При закрытии окна основного клиента или выборе **Esc → Оставить сессию в фоне** основной процесс продолжает поддерживать исходное соединение с сервером. Основной компьютер должен оставаться включённым и не уходить в сон.

Открыть приглашение снова: **Esc → Общая сессия** или **`.session`** в чате основного клиента. Скрытое окно можно вернуть через значок **Z** в системном трее; если трей недоступен, окно останется свёрнутым в панели задач. Кнопка **Вернуть управление на этот ПК**, команда **`.session release`** или `/zo… release` со второго ПК возвращает управление. При отключении второго ПК управление также возвращается автоматически.

**Закрыть сессию** или **`.session stop`** отключает гостей и закрывает интернет-туннель. На втором ПК управляющий может выполнить `/zo… stop`: сессия закроется, скрытое окно основного клиента появится снова. Секрет и публичный адрес могут меняться при новом создании сессии.

Способ подключения, настройки «Всегда открывать общую сессию» и сообщений сохраняются в `config/zenithopus-session.properties`. Автоматическое открытие изначально выключено. При обновлении старой сборки с включённым автоматическим LAN-режимом он сохраняется локальным до явного выбора Интернета. Пароль и учётные данные в файл не записываются.

Если подключение не проходит:

- Проверь одинаковую версию **Minecraft Java 1.21.11** на обоих ПК и актуальный адрес. Bedrock и 26.2 в этой сборке не поддерживаются.
- Интернет-адрес обычно появляется через несколько секунд. Если ретранслятор недоступен или сеть блокирует QUIC/UDP, через 30 секунд появится ошибка: можно нажать **«Повторить подключение»** или **«Использовать локальную сеть»**. Локальный адрес не выдаётся за публичный.
- Публичный адрес действует, пока работает сессия и есть связь с e4mc. При закрытии сессии туннель и связанные с ним подключения закрываются. Во время игры окно основного клиента можно скрыть — это не закрывает туннель.
- Для LAN проверь один роутер и адрес с портом. Для интернет-режима второй ПК использует показанный домен e4mc, а не домашний IP основного ПК.
- Для второго ПК не подходит `127.0.0.1`: это адрес самого устройства. Если в окне появился только он, у основного ПК не обнаружен локальный IPv4.
- При нескольких сетевых адаптерах выбран адрес домашней сети `192.168.…`, затем `10.…`. Если выбран виртуальный адаптер, используй IPv4 основного Wi-Fi/Ethernet с тем же показанным портом.
- Для LAN Windows может блокировать входящие подключения Java. Проверь разрешение Java для своей частной сети. Гостевая Wi-Fi-сеть и изоляция клиентов на роутере также могут запрещать связь между устройствами.
- После обновления мода перезайди на игровой сервер, чтобы клиент сохранил данные первоначального подключения.
- Данные мира передаются со стандартным сжатием Minecraft; второй ПК сам согласует его при входе. Во время активной сессии лимит частоты основного клиента не снижается ниже 60 FPS при сворачивании или бездействии, чтобы обработка управления не задерживалась. Это может увеличить нагрузку относительно обычного свёрнутого клиента.
- Если оба ПК подключены к одному роутеру, режим «В одной сети» использует прямое подключение и не добавляет маршрут через e4mc. Интернет-режим зависит от задержки и доступной скорости пути до ретранслятора; сжатие уменьшает трафик, но не устраняет сетевую задержку.

Соединение с игровым сервером принадлежит основному процессу Minecraft: принудительное завершение Java, сон, перезагрузка, потеря сети или выключение основного ПК завершит его. Сервер также может отключить игрока по своим обычным правилам. Изменение протокольной конфигурации/перевод на другой сервер закрывает текущую локальную сессию; после загрузки её можно создать заново. Для серверов, требующих клиентские моды, обычному Minecraft может не хватить их ресурсов и логики.

Это размещение на основном ПК с ретрансляцией входящих соединений, а не перенос игры на чужой сервер. Игровой сервер продолжает видеть исходное соединение основного ПК. Интернет-подключения проходят через встроенный туннель к локальному порту; прямые входящие подключения к этому порту по-прежнему принимаются только с локальных адресов.

Проверки разработчика: `gradlew.bat sessionProtocolTest` проверяет кадрирование, обработку повреждённых пакетов, vanilla login, идентификаторы управления, фрагментацию управляющих сообщений туннеля, адреса ретранслятора и отмену запуска. `gradlew.bat sessionTunnelSmoke` отдельно проверяет реальный публичный туннель через e4mc на временном Minecraft status/ping endpoint без открытия окна игры. `gradlew.bat build` собирает мод и запускает офлайн-проверки. Полный игровой сценарий на двух физических устройствах и все сторонние игровые серверы требуют отдельной проверки.

Исходный протокол и сервис: https://github.com/vgskye/e4mc-minecraft-architectury и https://github.com/vgskye/e4mc-quiclime. Лицензии библиотек и уведомления находятся в `src/main/resources/licenses/session-tunnel` и упакованы в мод.
